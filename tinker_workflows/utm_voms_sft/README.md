# Tinker workflow: UTM + VOMS(CTW) sequential SFT

This folder contains supervised fine-tuning workflows using the **Tinker Training API** for Solomonoff Induction approximation.

## Available Recipes

### 1. `bloem_ctw_sft.py` - Bloem+CTW Fine-Tuning (NEW)

Fine-tunes pretrained LLMs (Llama, Qwen) on universal data using:
- **Bloem buffer**: Iteratively refined sequences from randomly-weighted LSTMs
- **CTW trees**: M-ary Context Tree Weighting with curriculum learning

```bash
# Quick start
python bloem_ctw_sft.py --base_model meta-llama/Llama-3.2-3B --num_steps 5000

# Full configuration
python bloem_ctw_sft.py \
    --base_model meta-llama/Llama-3.2-3B \
    --lora_rank 64 \
    --bloem_buffer_size 30000 \
    --seq_length 2048 \
    --num_steps 10000 \
    --data_source bloem_ctw
```

See [Bloem+CTW Documentation](#bloemctw-fine-tuning) below.

### 2. Sequential UTM + VOMS (Original)

Sequentially fine-tunes a base model (via LoRA) on:

- Stage 1: **UTM** data (generated by `data/utm_data_generator.py`)
- Stage 2: **VOMS** data, here implemented as **CTW** sequences (generated by `data/ctw_data_generator.py`)

This is plain next-token prediction (SFT with `cross_entropy`) and does not require instruction prompts.

## UTM + VOMS Fine-tuning with Tinker

This workflow demonstrates supervised fine-tuning of language models on UTM and VOMS (CTW) data using the Tinker API, following the patterns from the [Tinker Cookbook](https://github.com/your-org/tinker-cookbook).

## Features

- Sequential fine-tuning on UTM and CTW (VOMS) data
- Support for Qwen base models (and other HuggingFace models)
- On-the-fly data generation
- Robust checkpointing and metrics logging
- Jupyter kernel integration
- Cost estimation for training runs

1. Install dependencies:
   ```bash
   pip install -r requirements.txt
   ```

2. Set your Tinker API key:



## Configuration

Edit `config.json` to configure your training run. Here's an example configuration:

```json
{
  "base_model": "Qwen/Qwen3-30B-A3B",
  "lora_rank": 8,
  "adam": {
    "learning_rate": 1e-4,
    "beta1": 0.9,
    "beta2": 0.999,
    "eps": 1e-8
  },
  "batch_size": 8,
  "seq_length": 1024,
  "save_every": 100,
  "log_every": 10,
  "output_dir": "outputs/utm_voms_sft",
  "seed": 42,
  "stages": [
    {
      "name": "utm",
      "steps": 1000,
      "utm": {
        "num_states": 5,
        "num_symbols": 5,
        "max_steps": 100
      }
    },
    {
      "name": "ctw",
      "steps": 1000,
      "ctw": {
        "depth": 3,
        "num_rules": 5
      }
    }
  ]
}
```

## Training

Start a new training run:
```bash
python train.py --config config.json
```

Resume from the latest checkpoint:
```bash
python train.py --config config.json --resume
```

Monitor training logs in `outputs/utm_voms_sft/training.log` and metrics in `outputs/utm_voms_sft/metrics.jsonl`.

## Checkpointing

The training script automatically saves checkpoints according to the `save_every` setting. Checkpoints are stored in the `output_dir/checkpoints` directory, with metadata in `checkpoints.jsonl`.

To resume from a specific checkpoint:
```bash
python train.py --config config.json --resume --checkpoint path/to/checkpoint
```

## Troubleshooting

### Common Issues

1. **CUDA Out of Memory**
   - Reduce `batch_size` or `seq_length` in the config
   - Use gradient accumulation if supported

2. **Checkpoint Loading Failures**
   - Verify the checkpoint path is correct
   - Ensure the model architecture matches the checkpoint

3. **Tokenization Errors**
   - Make sure the tokenizer supports your model
   - Check for special tokens that might need to be added

### Getting Help

For issues not covered here, please refer to the [Tinker Cookbook](https://github.com/thinkingmachines-lab/tinker-cookbook) or open an issue in the repository.

## Bloem+CTW Fine-Tuning

### Architecture

```
┌─────────────────────────────────────────────────────────────────┐
│                         LOCAL (CPU)                              │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────────────┐  │
│  │ LSTM Source │───▶│ BloemBuffer │───▶│ Batch Conversion    │  │
│  │ (reweight)  │    │ (30k seqs)  │    │ (tokens → Datum)    │  │
│  └─────────────┘    └─────────────┘    └──────────┬──────────┘  │
│                                                    │             │
│  ┌─────────────┐                                   │             │
│  │ CTWGenerator│───────────────────────────────────┤             │
│  │ (curriculum)│                                   │             │
│  └─────────────┘                                   │             │
└────────────────────────────────────────────────────┼─────────────┘
                                                     │
                         ┌───────────────────────────▼───────────────┐
                         │                 TINKER API (GPU)           │
                         │  forward_backward(datums, "cross_entropy") │
                         │  optim_step(adam_params)                   │
                         │  save_weights_for_sampler() → sampling     │
                         └───────────────────────────────────────────┘
```

### Key Parameters

| Parameter | Default | Description |
|-----------|---------|-------------|
| `bloem_buffer_size` | 30000 | **CRITICAL**: Must be large to prevent curriculum exhaustion |
| `seq_length` | 2048 | Context length (affects memory usage) |
| `bloem_temperature` | 0.3 | LSTM sampling temperature (0.1=deterministic, 1.0=random) |
| `ctw_max_depth` | 16 | Maximum CTW tree depth |
| `ctw_curriculum_steps` | 5000 | Steps to ramp arity from min to max |
| `data_source` | "bloem_ctw" | "bloem", "ctw", or "bloem_ctw" |
| `bloem_ratio` | 0.5 | Fraction of batch from Bloem (rest from CTW) |

### Chinchilla-Optimal Configuration

For 10k steps with batch_size=32 and seq_length=2048:
- Total tokens: ~655M
- Optimal model: 8B+ parameters (LoRA on Llama-3.1-8B)

```bash
python bloem_ctw_sft.py \
    --base_model meta-llama/Llama-3.1-8B \
    --lora_rank 64 \
    --batch_size 32 \
    --seq_length 2048 \
    --num_steps 10000 \
    --bloem_buffer_size 30000
```

### Monitoring Training

Key metrics to watch in logs/W&B:
- `train_nll`: Should decrease steadily
- `bloem_iterations`: Should increase slowly (target: 3-7 at completion)
- `ctw_step`: Curriculum progress

**Warning signs:**
- `bloem_iterations > 10` early → buffer too small, restart with larger buffer
- `train_nll` plateaus early → LR too low or model capacity saturated

### Checkpointing

Checkpoints include:
- Model weights (LoRA adapters)
- Optimizer state
- Bloem buffer contents and update counts
- CTW curriculum step

Resume with:
```bash
python bloem_ctw_sft.py --config config.json --resume
```
